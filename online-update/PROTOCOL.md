# Online release protocol 1

The client uses a pinned RSA public key to authenticate `update-channel/latest.json` with detached `latest.sig` (RSA PKCS#1 v1.5, SHA-256). The pointer contains the release timestamp/sequence, immutable catalog URL, byte size and SHA-256. The highest authenticated sequence and catalog hash are persisted to reject replay and equivocation on an existing client. First installation relies on the key shipped in the bootstrap downloaded from this repository.

The complete catalog maps each pack-relative path to size, SHA-256 and an immutable ZIP object. Payload paths are restricted to the published TGCNV/TGO game layout and TGCNV map cache. Seven root files contain the existing installer, wrappers, guide, manifest and checksums. Assets are restricted to this repository's GitHub Releases; redirects must stay on HTTPS GitHub infrastructure. File names, links, archive bounds, path collisions and hashes are checked before installation.

`build_catalog.py` verifies the complete pack manifest and SHA256SUMS, creates deterministic objects and compares every selected source file before and after building. Unchanged path/size/hash triples reuse old asset references. Changed and new files form new objects; removed files disappear from the catalog. Payload groups target 256 MiB raw size; metadata is separate. Each ZIP is below 2 GiB. An unchanged file may still require its original ZIP group when installing from scratch.

`Update.ps1` copies matching installed files into a fresh staging pack, fetches missing groups, verifies every file, and invokes the existing signed `Setup.ps1`. The installer backs up and replaces managed mod/cache/native roots. This is a differential download followed by a complete verified local installation; it is not binary delta patching. The installer handles deleted files and transactional rollback. Saves remain outside the managed payload. The original installer remains responsible for native-loader, EXE, process and game-version checks.

The verified installer and signed metadata are retained locally before applying. `Restore-Update.cmd` authenticates this cached package and invokes the existing journal-based restore without network access. Interrupted downloads can be retried; verified cached objects are reused. User-modified mod files are preserved in the installer's backup and replaced with the release content. Client binaries/scripts themselves are not silently self-updated.

Publishing requires explicit GitHub CLI authentication on the publisher PC. The private signing key is DPAPI-protected for the current Windows user and stored in a private directory outside all published files. Key rotation requires a client migration. Never include the key, authentication config, private diagnostics or game originals in repository commits or release assets.

Upload immutable objects, catalog and bootstrap to a draft release, verify GitHub's asset SHA-256 and lengths, then publish it. Advance the small signed channel last. Clients fail closed during the two-asset replacement window; rerun if a concurrent publication causes a signature mismatch. A failed pointer replacement attempts to restore the previous pair. Keep remote objects referenced by the latest catalog, even when local distribution retention removes older full ZIPs.

`publish_latest.py --base <distribution-tools-directory> --gh <gh.exe>` is the automation entry point. Run it only after the local publication's source consistency, native dependencies, map signatures, ZIP and installer validation gates pass. It reads `release-state.json`, verifies the selected published snapshot, builds/reuses objects, signs, uploads, checks the public channel and atomically records `online/online-state.json`. It never touches installed game files. Existing development holds and live-game validation limitations remain in effect.

Pure Python catalog checks: `python -B -m unittest test_catalog -v`. Windows integration and adversarial tests are retained in the local distribution audit directory. They use private fixture copies with transport/process substitutions; production code exposes no test bypass.
