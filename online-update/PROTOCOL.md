# Online release protocol 2 — stable installer and GHCR

The client authenticates one JSON envelope at the fixed raw GitHub URL `Yukino-Chan/TGC-Anime-Total-Overhaul-Korean/update-feed/channel.json`. Its base64 channel bytes and signature use the existing pinned RSA-3072 key, PKCS#1 v1.5 and SHA-256. Signed schema 2 metadata includes the release sequence, immutable GHCR catalog URL, size and hash. A single Git commit publishes both bytes and signature atomically.

The client keeps `highest-sequence-v2.json` and rejects sequence rollback or a changed catalog at the same sequence. The legacy watermark remains a minimum sequence during migration; an equal sequence is allowed once to change only the storage protocol. The new updater does not offer offline rollback from cached schema 1 receipts. Existing download objects remain reusable; preexisting backup journals are left untouched. Old installers must be downloaded once again because their channel URL is fixed.

The complete catalog maps each pack-relative path to size, SHA-256 and an immutable ZIP object. Payload paths are restricted to the published TGCNV/TGO game layout and TGCNV map cache. Eight root files contain the existing installer, wrappers, guide, manifest and checksums. New assets use exact `https://ghcr.io/v2/yukino-chan/tgcnv-patches/blobs/sha256:<digest>` URLs. Anonymous pull tokens have a fixed scope and are kept only in memory for 240 seconds. A 401 refresh is retried once. Authorization is attached only to the initial GHCR blob request, never to redirected GitHub CDN requests. Redirects are HTTPS-only, bounded to five, and restricted to GitHub hosts; foreign GHCR namespaces are refused. Legacy same-repository release URLs remain parsable for cached recovery catalogs. File names, links, archive bounds, path collisions and hashes are checked before installation.

`build_catalog.py` verifies the complete pack manifest and SHA256SUMS, creates deterministic objects and compares every selected source file before and after building. Unchanged path/size/hash triples reuse old asset references. Changed and new files form new objects; removed files disappear from the catalog. Payload groups target 256 MiB raw size; metadata is separate. Each ZIP is below 2 GiB. An unchanged file may still require its original ZIP group when installing from scratch.

`Update.ps1` copies matching installed files into a fresh staging pack, fetches missing groups, verifies every file, and invokes the existing signed `Setup.ps1`. The installer replaces managed mod/cache/native roots without creating backups. This is a differential download followed by a complete verified local installation; it is not binary delta patching. Whole-folder replacement removes obsolete files. There is no rollback; rerun the same verified installer to finish an interrupted installation. Saves remain outside the managed payload. The original installer remains responsible for native-loader, EXE, process and game-version checks.

The verified incoming pack is staged before applying and temporary files are cleaned up when the updater exits. `Restore-Update.cmd` only explains the overwrite-only policy; it does not restore files. A small current installation journal remains at `TGCNV_Install/receipt.json`. Interrupted downloads and installations can be retried; verified cached objects are reused. User-modified files inside managed mod/cache roots are replaced without a saved copy. `tgcnv_lua51_ori.dll` is the required original Lua runtime dependency, not a previous-version backup. Client scripts are not silently self-updated; download the new installer ZIP for this revision.

Publishing requires explicit GitHub CLI authentication on the publisher PC. The private signing key is DPAPI-protected for the current Windows user and stored in a private directory outside all published files. Key rotation requires a client migration. Never include the key, authentication config, private diagnostics or game originals in repository commits or release assets.

Upload immutable ZIPs and catalog to `ghcr.io/yukino-chan/tgcnv-patches`; a lowercase release tag names an OCI manifest referencing every object. Conflicting immutable tags abort. Never garbage-collect a blob still referenced by any supported catalog. No Docker runtime is required.

Before publishing, verify anonymous manifest/blob metadata, download and SHA-256-check objects using the production Windows transport, and reconstruct every catalog file. Verified public object downloads can be reused from the publisher cache after rehashing. The fixed GitHub Release `installer` has only `TGC-Online-Installer.zip` as a manually attached asset. Verify its GitHub asset digest and anonymous download, then advance the feed atomically, verify the public signed feed and catalog, and write online state last. GitHub also displays its automatic source archives; those are not mod installers.

Failed publication can resume using immutable objects and local validation records. Old dated releases were retired only after the migration passed all public download and client checks. The automation updates this same installer release rather than creating dated releases. A publisher lock excludes concurrent runs. The repository remains a public TGC fork; master contains the published TGCNV/TGO data and related updater/documentation sources; original upstream files remain in commit history.

`publish_latest.py --base <distribution-tools-directory> --gh <gh.exe>` is the automation entry point. Run it only after the local publication's source consistency, native dependencies, map signatures, ZIP and installer validation gates pass. It reads `release-state.json`, verifies the selected published snapshot, builds/reuses objects, signs, uploads to GHCR, checks the stable installer and public channel and atomically records `online/online-state.json`. It never touches installed game files. Existing development holds and live-game validation limitations remain in effect.

Pure Python checks: `python -B -m unittest test_catalog test_ghcr_store test_publish_ghcr -v`. GHCR transport checks: Windows PowerShell 5.1 `Test-Ghcr.ps1`. Windows integration and adversarial tests are retained in the local distribution audit directory. They use private fixture copies with transport/process substitutions; production code exposes no test bypass.

## Stable public names

The offline download is always `TGCNV-TGO.zip`, accompanied by `TGCNV-TGO.zip.sha256` and `TGCNV-TGO-설치안내.txt`. Its top-level directory is `TGCNV-TGO`. Public status messages and release notes do not expose timestamp-based release identifiers. Internal immutable release IDs, signed sequence validation, GHCR versions and audit timestamps remain intact. New installations keep a small current-state journal rather than old-version backup journals. Legacy dated archives remain readable; publication accepts only the fixed name or the exact legacy release filename inside the configured distribution root. Replace the public file only after validation, then update its checksum, guide and release state before cleaning older dated copies.
