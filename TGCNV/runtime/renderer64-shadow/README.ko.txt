TGCNV Renderer64 Shadow 0.1.0 — engine 0.6.8.15

게임을 시작하면 엔진이 이 관리 프로그램을 숨김 상태로 한 번 실행합니다.
현재 게임 PID의 관측 파일이 완성되면 최대 4개의 캡처 프레임을 x64 작업자로 재생하고,
반환된 부분 영역의 해시·색상·깊이 형식을 검증한 뒤 종료합니다.

이 패치는 실게임 연결을 위한 검증 단계입니다.
게임 화면은 기존 D3D9 그리기를 계속 사용합니다.
실게임 지형과의 합성, 원본 GPU 버퍼의 완전한 일치, FPS/메모리 개선을 완료했다고 뜻하지 않습니다.
지원 모델은 기존 연구에서 확인한 Iori 첫 8개 submesh와 고정 shader/cache입니다.
알 수 없는 캡처·미지원 해상도/상태·손상·시간 초과는 거부하고 게임 그리기는 계속됩니다.

사용
1. 기존 TGCNV 실행기로 실행하고 캠페인 지도에 진입합니다.
2. Iori 모델이 보이는 장면에서 관측 기록이 모이면 자동 검증을 수행합니다.
3. %LOCALAPPDATA%\TGCNV\logs\renderer64-shadow-<PID>-<tick>\summary.json을 확인합니다.
   complete: 이 캡처의 x64 재생과 응답 형식 검증이 완료되었습니다.
   unsupported: 현재 고정 캐시와 호환되지 않는 캡처입니다.
   rejected: 해시·형식·실행 파일·작업자 응답 등의 검증에 실패했습니다.
   timeout: 10분 안에 관측 파일이 완성되지 않았거나 작업자 응답이 지연되었습니다.
   worker_started/worker_bits/worker_stopped는 실제 실행 결과를 나타냅니다.
   complete가 실게임 스크린샷과의 픽셀 일치를 입증하는 것은 아닙니다.
4. 다음 실행부터 끄려면 runtime/data/tgcnv_renderer64_shadow.txt의 shadow=0으로 변경합니다.

관측 설정은 기존 tgcnv_renderer64_probe.txt를 따릅니다.
이 파일럿은 expected_records가8/16/24/32인 경우만 실행합니다.
게임의 임시 지도 캐시 생성 실행에서는 검증 관리 프로그램을 시작하지 않습니다.
관리 프로그램은 캡처를 기다리며 최대10분 후 종료하고, GPU 작업자는 최대4프레임 처리 후 종료합니다.
게임이 종료되면 소유한 두 하위 프로세스도 함께 종료됩니다. 별도 서비스/자동 시작 등록은 없습니다.

runtime/renderer64-replay의 기존 수동 재생 도구는 유지됩니다.
이 디렉터리의 실행 파일/셰이더/캐시를 수동 변경하면 무결성 검증에서 거부될 수 있습니다.
진단 파일과 shader compile 출력은 게임 로그 폴더 아래에만 생성합니다.
xxHash 라이선스는 LICENSE.xxHash.txt에 있습니다.
